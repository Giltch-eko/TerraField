## Use
1. Start the application (see README), open New analysis. Above the map enter a country, region, settlement, address, identifiable landmark/farm or `latitude, longitude`, then press Enter or Search. Search is not sent while typing. Select a matching result. Results represent provider reference points, not verified farms; click the actual field to set a more precise location.
2. To set an exact point, enter decimal latitude and longitude and choose Navigate. Latitude −90 through 90 and longitude −180 through 180 are accepted. Clicks and manually entered/search points show six decimals. The map itself uses Web Mercator and visually clips latitudes beyond about ±85.05112878°: the application warns and retains the true coordinate, but the polar marker is shown at the edge. Do not use that visual marker as a polar navigation fix.
3. Choose Draw boundary, click three or more vertices (or enter coordinates and choose Add outline vertex each time), then Finish. Existing outlines can be edited by dragging vertices and finishing, cancelled to restore the previous selection, or cleared. Undo removes the last draft vertex or reverses a drag during the current edit. Keyboard-only users can add vertices using coordinate fields; editing an existing vertex currently requires dragging or redrawing. Self-crossing, degenerate, dateline-crossing, polar, over-1°-wide/high and >100-vertex polygons are rejected. The area-weighted centroid from a local equirectangular projection and spherical surface area are approximations appropriate to small field polygons—not legal parcel boundaries or geodesic surveying. A centroid outside the ring is replaced with an interior scanline point; coordinates are checked after six-decimal rounding. Verify the location.
4. On Global Soil Data, select **Use this field in New Analysis** to transfer the point or finished polygon interior representative point into profile coordinates. Exploring on the soil page alone does not change the profile. New locations clear old SoilGrids-derived pH/texture and current modelled weather; manually entered or illustrative inputs remain with a warning because the app cannot infer their source. Review rainfall, climate, soil and nutrients before running the existing screening. During polygon editing, the previous profile location remains until Finish. The existing engine can operate with manually entered inputs if online services fail.
5. Coordinates and finished geographic vertices are stored in `sessionStorage` for that browser tab (where available), restored on reload and cleared with Clear selection, profile reset, loading an example or when the browser-tab session ends. Browser restore settings can affect session retention. Field crop/dates remain in memory only. New reports retain matching validated polygon geometry, approximate area and method; earlier reports may contain only coordinates and name. Session storage can be inaccessible in privacy modes. Do not use shared devices for sensitive coordinates.

## Global Soil Data integration
The same map is also available on Global Soil Data. Choosing a search result or map point automatically fills its latitude/longitude fields, without requesting soil data or silently changing the current crop profile. The original soil search also updates the map. Select “Show coordinates on map” for manually entered soil lookup coordinates.

## Providers, coverage, privacy, production
- The existing server queries **Photon**, which searches worldwide OpenStreetMap data, and **Open-Meteo Geocoding** (GeoNames); search results show their source. The shipped offline GeoNames index is absent. They can return incomplete, ambiguous, stale or missing places; remote or private farms and all worldwide addresses are not guaranteed. Search supports text and parsed decimal coordinate pairs. Optional reverse geocoding is not implemented. Sources: [Photon](https://photon.komoot.io/), [OpenStreetMap attribution](https://www.openstreetmap.org/copyright), [Open-Meteo geocoding](https://open-meteo.com/en/docs/geocoding-api).
- Place-name queries are sent from the server to providers; valid decimal coordinate-pair searches are parsed locally by the server. the map browser also sends tile requests to EOX. Consider the privacy implications of names, addresses and field coordinates. The app does not require or ship a private geocoder key. Results may be cached in process memory; server rate limiting, query caching, timeouts and in-flight coalescing are process-local. The UI uses submitted searches only, aborts obsolete requests and does not intentionally use autocomplete.
- Photon public service is a community fair-use service and may throttle or fail; self-host or arrange an appropriately licensed provider for sustained or commercial usage. Open-Meteo's free tier is for non-commercial/prototype use and subject to its published fair-use limits and attribution. Check [Open-Meteo pricing](https://open-meteo.com/en/pricing) and obtain an appropriate commercial licence/provider and server-side configuration for commercial operation. The current code is **not** wired for a paid Open-Meteo endpoint/key. Multiple workers/instances need a shared rate limiter, cache and abuse controls. Recheck current provider terms before deployment.
- The underlying imagery remains the public EOX Sentinel-2 cloudless 2016/17 mosaic, approximately 10 m, not live, with CC BY 4.0 attribution on the map. EOX public service is reasonable-use with no SLA; check [EOX FAQ](https://cloudless.eox.at/documentation/faq). No new imagery provider or extra map library was introduced.

## Setup and tests
Node 24 is required. Extract the ZIP, run `npm ci`, then `npm start` and open the local address printed in the terminal. For browser tests install Chromium with `npx playwright install chromium`; additional system dependencies may be needed. With the server on its default port 8000, use `npm run test:global-map`. For a different port, set `TERRAFIELD_TEST_URL` to the local server URL when running tests. The test makes real network queries for Hyderabad and São Paulo and can fail if external services are unavailable; outage, no-result and request-race checks also use controlled mocks. No deployed URL is claimed. The backend test suite still has one genuine missing-GeoNames-index failure; do not represent it as a pass.
