# API documentation

The detailed current profile schema, examples, errors, GET routes and organic requests are in [API.md](API.md) and [ORGANIC_ADVISOR.md](ORGANIC_ADVISOR.md). Same-origin JSON, no separate API service. `GET /api/health` checks SQLite and reports the **bundled historical library count**, not an independently computed live catalogue count. `GET /api/catalogue` reports the actual DB's filtered and overall totals. `GET /api/crops` returns the distinct 21 screening profiles.

## Reports and optional geometry (2026 addition)
`POST /api/reports`, `/api/farm-plan` GET/PUT, and report GET/PATCH/DELETE require `X-Workspace-Key`: 64 hexadecimal characters; this is a bearer secret, not a login. Report creation accepts `{ "profile": {...}, "title": "Field", "field": {"geometry": {"type":"Polygon","coordinates":[[[78,17],[78.01,17],[78.01,17.01],[78,17.01],[78,17]]]}} }`. The ring is closed, `[longitude,latitude]`, exactly one ring, no holes; 3–100 vertices, non-self-intersecting, span at most 1° in either dimension, inside Mercator latitude bounds, area greater than 1 m² and a representable strictly interior point. Profile latitude/longitude must match the recomputed representative point within 0.000001 degrees. Geometry is optional or null. A malformed, out-of-scope or mismatched geometry returns 422. The server discards a submitted area and computes `field.area_m2`, `field.representative_point`, `field.method`, `field.source`, and canonical geometry; it also recalculates the screening result from the profile. GET returns `field`, or null for older/point-only reports. A different valid workspace secret gets 404; malformed/missing secret gets 401. Title is 1–80 characters. JSON body max 32768 bytes; too-large is 413, wrong media 415, malformed JSON 400. Errors do not expose exception stacks.

`POST /api/recommendations` computes without saving. Reports are snapshots, not automatic updates. CSV export is client-side and print/PDF uses the browser; no server export endpoint is claimed.
