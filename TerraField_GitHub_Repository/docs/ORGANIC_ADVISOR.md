# Organic-first farming advisor — implementation and limitations

## Status and safety
This is an **organic-first planning prototype**, not the complete location-validated advisory service described in the requirements. It preserves the existing 21-crop ECOCROP-based screening engine, database, satellite map and catalogue. The crop index is not an organic certification, probability, yield forecast or guarantee. No synthetic fertilizer or conventional synthetic pesticide/insecticide is recommended. The advisor does not issue any organic product, recipe, rate, application interval or diagnosis either. Natural and biological products are not automatically safe, legal, registered or acceptable for a particular organic certification. Confirm current product registration for crop, pest and place, and certifier requirements, with qualified local extension and the relevant authorities before any intervention.

Input provenance matters: illustrative examples are explicitly marked; SoilGrids and current weather are modelled, not lab/seasonal measurements; N/P/K remain unscored and cannot determine deficiencies. General organic considerations are labelled as such, not displayed as field-specific prescriptions. Guidance does not claim the farm, produce or input is certified organic. Benefits and limitations depend on local conditions, and yield improvement is never guaranteed.

## What works now
- The results page and sidebar link to **Organic farming guide**. Select any of the 21 engine-supported crops and load its current profile-specific score and factor explanations. Broad ECOCROP crop pH, temperature, annual rainfall, texture and historical duration ranges are displayed with provenance and limitations. Existing crop screening is unchanged; other catalogue plants are not automatically scored.
- Source-backed general organic soil and method cards discuss mature compost/manure, vermicompost and biological inputs, covers/green manure, soil cover and erosion, prevention/monitoring, crop diversity and water conservation. Each card identifies possible benefits, practical assessment steps and limits. These are **not** ranked for the field, verified locally or equivalent to a crop-specific cultivation plan. No rates, recipes, disease-specific treatments or product registrations are supplied.
- Natural crop health records symptoms only for the current response and recommends diagnostic next steps, prevention and local expert consultation. It does not identify a disease or analyse photographs. Organic products must not be assumed harmless.
- Water calculator asks for a user-selected crop, area (ha), user-supplied stage, ETo (mm/day), crop coefficient Kc, period (whole days), effective rainfall (mm) and irrigation efficiency (%); available water (m³) is optional. ETc = ETo × Kc × days; net = max(0, ETc − effective rain); gross = net / efficiency; volume = gross mm × hectares × 10 m³. It assumes no change in soil storage, capillary rise, leaching, flooding or runoff; it is not a daily watering schedule. The crop or stage does not automatically select a Kc. No measured soil moisture, live ETo, weather or rain is fabricated.
- Organic calendar uses the farmer's planting date and **farmer-entered** minimum/maximum variety duration to calculate an arithmetic window, and stores farmer-entered task dates and completion statuses. It does not invent stage dates or send reminders. Entries display overdue/upcoming in the browser's local date. Add a task after confirming a real date locally.
- Cost planner records farmer estimates or historical actuals and optional area, currency, harvest quantity/unit and price. Unknown cost categories stay unknown; total and profit are withheld until required values are entered. No yield or price is generated. Only one crop plan is stored per browser workspace; the UI blocks applying its saved calendar/costs to a different crop. The plan is stored in the additive SQLite `farm_plans` table keyed by the same hashed browser workspace key used for reports. Keep database and browser key backups. This is not production account security; there is no multi-device sync, locking/versioning or recovery, and concurrent browser tabs can overwrite each other.
- **Ask TerraField** is a limited deterministic keyword-based assistant that can include the currently open analysis. It is not an AI model and does not diagnose or recommend pesticides. It does not store conversations. It requests missing local context and links sources where available.
- Global Soil Data now contains the existing Leaflet map. A map place search, map click or finished outline fills the soil lookup's latitude and longitude automatically; selecting a result in the original soil search also positions the map and fills both fields. Coordinate-pair searches are accepted directly. Soil data is fetched only when the user requests it. Exploring a different point on the soil page does **not** silently change the crop profile. Manual soil fields can be displayed on the map using “Show coordinates on map.” Search results are approximate reference points; choose the actual field.

## Not implemented / not verified
Local crop-by-crop organic growing plans, planting/seed/spacing rates, crop-stage irrigation schedules, locally verified water coefficients, automatic daily recommendations, soil nutrient interpretation, crop/pest-specific prevention or treatment databases, biological agent/organic-product registrations or labels, photo analysis, diagnosis, planting arrangement compatibility, crop rotation rankings, intercropping recommendations, remote weather/market/yield forecasts, crop-stage event generation, push reminders and an external conversational AI are **not implemented**. Tabs explicitly say when evidence is missing. No state-specific Indian practice or pesticide recommendation has been verified; APEDA is an India-specific standard reference, not proof of a local product's approval. No agricultural outcome or safety validation, real farmer field trial, screen-reader audit, production deployment or nationwide regulatory review was performed.

Links were checked 2026-10-30; availability, standards, registrations and local recommendations can change. These sources do not certify the app's output or verify a farmer's location or inputs.

## API and code changes
Added `node-server/organic.js` (source-attributed general guidance), `node-server/advisor.js` (rule-based guide, calculations, safe triage and validation), additive routes and `farm_plans` table in `node-server/app.js`, `client/advisor.js` and UI changes to `client/index.html`, `client/app.js`, `client/styles.css` and `client/field-map.js`. No API key is used. The server validates request objects and returns 422 for invalid advisory inputs. The `X-Workspace-Key` header is required for farm-plan persistence. No credentials or user databases are bundled.

Endpoints, all same-origin JSON:
- `GET /api/advisor/organic-practices` — general practice cards, citations and limits.
- `POST /api/advisor/guide` — `{crop_id, profile}`; re-runs the existing score and attaches general organic considerations.
- `POST /api/irrigation/calculate` — `{crop_id, area_ha, eto_mm_day, kc, days, effective_rain_mm, efficiency_pct, available_m3?, stage?}`.
- `POST /api/farm-costs/calculate` — `{seed,fertilizer,irrigation,labour,protection,machinery,other,harvest_quantity?,price_per_unit?,record_type?,currency?,harvest_unit?,cost_area_ha?}`. Null/blank costs remain unknown.
- `POST /api/crop-health/diagnose` — `{crop_id, symptoms, stage, plant_part}`; returns **no diagnosis**, only safe next steps.
- `POST /api/crop-calendar` — `{crop_id,planting_date,min_days,max_days}`; arithmetic window from user inputs.
- `POST /api/advisor/ask` — `{question,crop_id?,profile?}`; deterministic rule-based response.
- `GET /api/farm-plan`, `PUT /api/farm-plan` — workspace-key-protected plan. PUT accepts `{crop_id,tasks:[{title,due_date,done}],planting_date?,min_days?,max_days?,costs:{...}}`. This replaces the workspace's one plan, not individual task records.

`npm ci` and Node 24 are required for browser tests; `npm start` runs the Node API/static frontend and creates SQLite tables. Install Playwright Chromium with `npx playwright install chromium` for tests. `npm run test:advisor`, `npm run test:advisor-browser`, `npm run test:global-map`, `npm run test:browser` and `npm run test:enhanced` use the existing environment. Browser tests need the server running; set `TERRAFIELD_TEST_URL` if not on port 8000. `npm test` currently reports 43/44: the one remaining failure is the absent offline GeoNames index. Detailed transcripts are in `tests/last_*_organic_run.txt` and `tests/last_advisor_*_run.txt`.
